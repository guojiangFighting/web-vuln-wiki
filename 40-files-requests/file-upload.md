# 文件上传漏洞（Unrestricted File Upload）

## 一句话
> 上传本身不是漏洞——「传上去的内容被当作代码执行」才是。判断上传安全的唯一分水岭：**上传的文件能否在服务器语境下被执行**。

## 它是怎么发生的
**根因**：上传功能要同时做对三件事——限制类型、控制落点、断开执行。任何一件没做对，攻击面就完整地暴露出来：

1. **类型限制失效**：黑名单/前端校验可绕（见场景）；
2. **落点可控**：文件名/路径来自用户输入（接[路径穿越](path-traversal.md)）；
3. **执行未断开**：文件落在 Web 可访问目录且扩展名会被解析器执行（`.php`/`.jsp`/`.aspx`），或 `.htaccess`/`.web.config` 被覆盖改写解析规则。

**关键认知**：Content-Type 是请求方自填的、扩展名是请求方自填的、magic bytes 可以伪造——**一切「请求方声称的东西」都不能作为安全依据**，只有服务端的存储与执行策略是真的防线。

## 攻击场景

### 场景一：直接上传脚本（黑名单绕过）
**目标**：黑名单禁了 `php`。**思路**：扩展名变体——`.php5`/`.phtml`/`.pht`（映射到 PHP 解析器）、大小写 `.PhP`、末尾点/空格（Windows 特性 `shell.php.` → `shell.php`）。
**结果**：上传后访问该 URL 即 RCE。每个解析器都有「除主扩展名外还认的」别名清单——白名单天然解决，黑名单永远列不全。

### 场景二：双扩展名与解析器歧义
**目标**：只允许图片扩展名但仍存进可执行目录。**思路**：`shell.php.jpg`——旧版 IIS/Apache 曾存在「按右起第一个可识别扩展名解析」或「目录名含 .php 则整目录按 PHP 解析」的历史行为；现代配置多已修复，测试时验证即可。
**结果**：能执行 = 高危；不能执行时此类 payload 仅作配置核对。

### 场景三：覆盖解析配置（.htaccess / .web.config）
**目标**：Apache（允许 `.htaccess`）或 IIS 环境。**思路**：上传名为 `.htaccess` 的文件，内容 `AddType application/x-httpd-php .abc`，随后 `.abc` 文件按 PHP 执行。
**结果**：一次上传永久改变执行策略——比传一个脚本更彻底，测试中是白名单场景下的重要检查项。

### 场景四：图片马（内容校验通过后仍被执行）
**目标**：服务端校验 magic bytes/图片合法性。**思路**：图片元数据段里夹代码，若文件仍以 `.php` 存储并被解析，注释内容照常执行。
**结果**：证明「内容校验」与「执行控制」是两件事——校验通过不等于安全。

### 场景五：竞争条件（Race）
**目标**：上传后「先保存、异步扫描、发现问题再删」的实现。**思路**：高并发上传+立即访问，命中「已保存、未删除」的窗口。
**结果**：与[竞态条件](../50-logic-concurrency/race-condition.md)同根——「时间窗内状态不一致」。

## 怎么发现它
- **手工测试**：逐项递进——① 上传合法文件确认功能与返回路径；② 换扩展名（白名单试探：每种脚本扩展名 + 变体）；③ 试 `.htaccess`/`.web.config`；④ 确认文件落点（响应路径、报错泄露）与**是否被解析**（访问后看行为，不是看下载）。
- **真假判断**：上传成功 ≠ 漏洞成立；**必须证明「内容被当作服务端代码执行」**（访问 URL 后出现执行痕迹）。静态资源域、对象存储直传、随机化文件名的实现通常不构成 RCE，此时评估降级为「上传策略弱点」。

## 常见绕过与进阶
- **前端校验**：直接改请求重发，前端校验等于没有。
- **MIME 校验**：Content-Type 是请求方自填的，改一行即过。
- **magic bytes 校验**：`GIF89a` 头 + 脚本内容拼接。
- **文件名校验**：接[路径穿越](path-traversal.md)（`name=../../x.php`）与随机化缺失（可枚举他人文件）。
- 思路主线：**「请求方声称的一切」（扩展名/MIME/文件名）都是不可信输入；服务端的「存储策略 + 执行策略」才是攻击面真正的边界**。

## 怎么修
1. **断开执行（治本第一）**：上传文件存对象存储或独立「静态域名」，该域不配置任何动态解析；落点目录无执行权限（nginx `location` 不交给 fastcgi）。
2. **服务端白名单扩展名 + 随机文件名**：文件名服务端生成（uuid），扩展名白名单映射，用户输入只作展示名。
3. **内容处理**：图片二次渲染（重编码剥离夹带内容）、深度校验 magic bytes；非图片类型走病毒/内容扫描。
4. **目录与权限**：上传目录禁执行、禁解析配置文件覆盖（Apache 禁 `.htaccess` 覆盖）。
5. **解压类功能**：逐条目路径校验（防[路径穿越](path-traversal.md)）+ 类型白名单。

## 常见误区
- **「上传了 shell 才算漏洞」**：能传「会被执行的任何内容」（.htaccess、模板文件、计划任务文件）都算；反之，传了 shell 但落点永不执行 = 只有存储滥用风险，评级完全不同。
- **「校验了 Content-Type 就安全」**：那是一行客户端代码，改包即过。
- **「限制扩展名 = 限制类型」**：扩展名只是名字；执行策略（目录/解析器配置）决定「什么会被执行」，后者才是安全边界。
- **「上传域隔离了就高枕无忧」**：还要确认隔离域「不解析动态语言」且与主域不共享 Cookie/信任边界（否则接[SSRF](ssrf.md)/[XSS](../20-frontend/xss.md) 放大）。
