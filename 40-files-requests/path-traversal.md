# 路径穿越（Path Traversal / LFI）

## 一句话
> 用户输入被拼进文件路径且未限定在基准目录内，`../` 让「读头像」变成「读任意文件」——文件系统没有 Web 路由的概念，路径字符串就是它的 API。

## 它是怎么发生的
**根因**：把用户输入拼进 `open()`/`fopen()`/`include` 类路径，而没有「先规范化、再验证基准目录前缀」。`../` 是所有操作系统通用的「上一级目录」，拼接后路径脱离预期范围：

```python
open("/var/www/uploads/" + request.args["name"])
```

`name=../../../etc/passwd` → 实际打开 `/etc/passwd`。当「读」进一步变成「包含/执行」（LFI：Local File Inclusion），危害从信息泄露升级到代码执行。

**触发三要素**：
1. 输入进入文件类 sink（读取、下载、包含、解压目标路径、日志写入路径）；
2. 路径拼接且未做规范化校验；
3. 结果可观察（内容回显、报错差异、行为变化）。

## 攻击场景

### 场景一：基础穿越读文件（有回显）
**目标**：文件下载/预览功能。**思路**：按目录深度补 `../` 到根，再走绝对目标。
**payload**：`?file=../../../../../etc/passwd`（Windows：`..\..\..\Windows\win.ini`）
**结果**：响应回显文件内容。逐层加 `../` 直到命中即可，多加无害。

### 场景二：编码变体（过滤生效时）
**目标**：黑名单过滤了 `../`。**思路**：用编码层错位让校验看到「非 ../」而文件系统收到「../」。
**payload**：`..%2f`、`%2e%2e%2f`、`..%252f`（双重编码）、`....//`（只做一次替换删除的过滤删完剩 `../`）
**结果**：与[编码与绕过](../00-basics/encoding-bypass.md)的原理完全一致——每种变体对应一种过滤写法。

### 场景三：LFI 从读到执行
**目标**：`include`/`require` 类 sink。**思路**：先读配置与日志文件定位可写且会被解析的内容（如 Web 服务器日志），把代码写入日志（通过 User-Agent 等可控头），再包含日志文件使其被解析执行——即「日志投毒」，属从读到执行的经典链（概念级，授权环境验证）。
**结果**：条件性 RCE。现代默认配置多已阻断了大部分链条，但「读」的价值本身就足够定高危。

### 场景四：PHP wrapper（协议面）
**目标**：PHP 应用的包含点。**思路**：`php://filter/read=convert.base64-encode/resource=index.php` 以 base64 读出源码（绕过「当 PHP 执行」的默认行为）。
**结果**：拿到源码后攻击面全面展开（隐藏端点、硬编码密钥）——这是 LFI 测试的第一招。

### 场景五：解压路径穿越（Zip Slip）
**目标**：上传 zip 并解压的功能。**思路**：zip 条目名本身可含 `../`，解压时写到基准目录之外。
**结果**：与上传结合的变体，本质相同——**路径来自不可信来源**。

## 怎么发现它
- **手工测试**：一切「文件名/路径参数」处（下载、导出、模板选择、语言包、头像裁剪）先打绝对路径（`/etc/passwd`）再打相对穿越；Windows 与 Linux 路径语法都试；观察内容差异与报错。
- **真假判断**：固定报错「文件不存在」可能是基准目录外的统一拒绝（好信号）也可能是校验生效——用 `../` 与 `....//` 区分过滤形态；回显二进制乱码不算读成功，读「确定内容」的文件（passwd/win.ini）才算实锤。

## 常见绕过与进阶
- **基准目录前缀校验被绕**：`/var/www/uploads/../../etc/passwd` 进入时前缀成立，规范化后已脱离——「校验在规范化前」的经典缺口。
- **截断（历史）**：`%00` 截断扩展名拼接，PHP 5.3+ 已修复，仅存于遗留系统。
- **绝对路径直接注入**：部分实现 `base + input` 时绝对输入整体替换（Python `os.path.join` 的语义）。
- 思路主线：**穿越的全部对抗都发生在「字符串校验」与「文件系统规范化」之间——修复只要把校验放到规范化之后，95% 的变体自动失效**。

## 怎么修
1. **根本不拼路径（治本）**：`file_id=3` 映射到服务端预定义路径——用户输入永远不是路径的一部分。
2. **必须用文件名时**：先规范化（`realpath`/`Path.resolve`），再断言「结果以基准目录为前缀」，两条缺一不可；规范化与校验的顺序是命门。
3. **解压安全**：逐条目校验目标路径在解压目录内（防 Zip Slip）。
4. **最小权限 + 分区**：应用进程只读必要目录；上传目录与代码目录分离。
5. **禁动态包含**：`include $user_input` 这类代码模式在审计中直接判死刑。

## 常见误区
- **「Linux 服务器用 `/`，不用测 `\`」**：混合与编码变体要试全；且 Java 的 File 类在多平台上行为有差异。
- **「读不到 /etc/passwd 就没有穿越」**：基准目录可能已在深层（需更多 `../`），或回显被禁——用盲测（时间/报错差异）与 LFI 链评估。
- **「过滤 ../ 就够了」**：编码变体与 `....//` 都能还出 `../`；真正的修复是「规范化后校验前缀」，过滤只是幻觉。
- **「路径穿越只能读文件」**：结合上传（Zip Slip 写任意路径）、包含（LFI→RCE）时是完整的执行链。
