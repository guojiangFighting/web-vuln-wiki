# 信息泄露（Information Disclosure）

## 一句话
> 单条泄露往往只是「低危的不体面」，但泄露信息组合起来就是攻击者的作战地图——版本号接已知漏洞、源码接隐藏端点、备份文件接整套数据库。评估信息泄露，永远按「组合价值」算。

## 它是怎么发生的
**根因**：把「对开发者可见」与「对互联网可见」划了等号。以下内容在生产环境常见且高频泄露：

| 泄露面 | 例子 | 组合价值 |
|--------|------|----------|
| 详细报错 | 堆栈、SQL 语句、框架版本 | 版本 → CVE 匹配；SQL → 注入点定位 |
| 源码与注释 | HTML 注释、TODO、接口地址、硬编码密钥 | 隐藏端点、凭据 |
| 目录列举 | `/static/`、`/backup/` 可浏览 | 直接下载全部文件 |
| 备份与临时文件 | `index.php.bak`、`db.sql`、`.tar.gz` | 整站源码/数据 |
| 版本控制目录 | `/.git/`、`/.svn/` | 重建整库源码与历史 |
| 环境配置 | `/.env`（数据库密码、云密钥） | 直接接管基础设施 |
| 调试接口 | `/actuator`、`/debug`、`phpinfo` | 运行时全部内部状态 |

**它为什么重要**：信息泄露极少独立成灾，但它是几乎所有攻击链的**第一步**——侦察质量决定后续攻击的精准度。

## 攻击场景

### 场景一：报错信息侦察
**目标**：触发并收集详细错误。**思路**：给参数传异常类型（字符串进数字位、超长值、畸形 JSON），观察 500 响应的堆栈与 SQL。
**payload**：`?id=abc`、非法 JSON、空 body
**结果**：从堆栈读出框架与版本、从 SQL 报错读出表结构——后续测试的靶图。

### 场景二：版本控制与配置文件
**目标**：`.git`、`.env`。**思路**：直接请求 `/.git/HEAD`、`/.env` 等固定路径（这些不是「猜」，是「查」）。
**payload**：`GET /.git/HEAD`
**结果**：`.git` 存在时可逐对象还原源码；`.env` 直接给数据库与云凭据——单项即可能达到高危/严重。

### 场景三：备份文件与目录列举
**目标**：开发遗留物。**思路**：对已知文件名试 `.bak`/`.old`/`.zip`/`.sql` 后缀；对静态路径确认是否开目录列举（`/static/` 返回文件列表）。
**结果**：`index.php.bak` = 无需穿越的源码获取。

### 场景四：调试与管理接口
**目标**：Spring Boot Actuator、Swagger、phpinfo。**思路**：请求常见调试路径并核对返回内容。
**结果**：`/actuator/env`、`/heapdump` 暴露配置与内存数据——这些接口设计给运维，泄露给互联网即事故。

## 怎么发现它
- **手工测试**：① 每个参数试「类型错误」触发报错并审读内容；② 查看一切响应的注释与隐藏字段；③ 固定路径清单（.git/.env/.svn/actuator/phpinfo/swagger）逐一核对；④ 静态目录测列举；⑤ 已知文件名 + 备份后缀字典。
- **工具**：字典探测（dirsearch/ffuf 概念）、nuclei 的泄露模板；JS 文件里的端点提取（LinkFinder 思路）。
- **真假判断**：404 与 403 的区分（403 常暗示文件存在）；`.git/HEAD` 返回 200 还要看能否取到对象（有的防护只挡列举不挡读取）；报错信息按「是否包含内部细节」分级，通用友好页不算泄露。

## 常见绕过与进阶
- **WAF 挡 404 目录列举**：改用具体文件名请求（列举被挡但单文件可读是常见组合缺口）。
- **`.git` 部分防护**：挡了 `/.git/` 列举但 `/.git/config`、对象文件可直读——逐对象还原即可。
- **响应头与 Cookie 信息**：`X-Powered-By`、session 名（`PHPSESSID`）本身即版本线索。
- 思路主线：**泄露测试的目标不是「找到一条」，而是拼出「攻击地图」——每条信息标注它能打开的下一扇门**。

## 怎么修
1. **统一错误页（治本且零成本）**：应用与 Web 服务器层都配；堆栈与 SQL 只进日志。
2. **部署产物审计**：CI 中禁止 `.git`/`.env`/备份文件进入部署包；静态目录关列举（`autoindex off`）。
3. **调试接口隔离**：actuator/debug/swagger 仅绑定内网或加鉴权；生产配置显式关闭调试模式。
4. **密钥不入代码与注释**：走配置中心/环境注入，历史泄露的密钥**必须轮换**（泄露即视为已失效）。
5. **安全响应头**：移除 `X-Powered-By`/`Server` 细节（低优先，但顺手）。

## 常见误区
- **「信息泄露都是低危」**：`.env` 里的云密钥、`.git` 整库、`heapdump` 内存快照单项即可接管系统——按内容价值定级，不按「它只是信息」定级。
- **「报错页不回显给用户就行」**：回显给搜索引擎缓存、日志聚合平台、第三方监控同样算暴露面。
- **「内网系统不用管」**：信息泄露的价值恰恰在横向移动——内网侦察的第一手材料常来自这些「没人管」的端点。
- **「关了 debug 模式就完事」**：`.git`、备份、注释、目录列举与 debug 模式无关，是部署与编码习惯问题——泄露面要逐项清单化治理。
